# 《猫狗大战家具》视觉规范 v0.1（审查稿）

状态：用于审核，**尚未接入运行时**。证据来自[参考录屏逐帧取样](../../../reference-analysis/IMG_4018/视觉风格取样与生产方式.md)、项目已确认的[Figma 首页图](../legacy-package-assets/figma-home.jpg)、[局内字体预览](../font-review.md)与当前局内组件。项目自身的玩法、安全区与资源约束优先于参考录屏。此前 `visual-system-v1/v2.png` 是未审概念图，不作为数值或图案来源。

[原创组件小样 v1](original-components-v1.png)只验证材质、厚度与状态的家族感。它没有文字，尚非透明切图；其中圆形爪印不能充当金币图标，卡牌底部徽章不能决定实际卡费位置。正式图标和布局遵循下表与现有规则。

## 1. 视觉方向与层级

1. **场景**：暖木色客厅与软垫、地毯构成家中感；全屏背景可延伸过安全区，但不能降低角色、家具、相框的辨识度。局内保持现有俯视战场与动作相机规则。
2. **主体**：猫狗和家具在地面有短接触阴影，轮廓先于细节可读。合照相框是守护目标，家具受击与合照受损位置必须一致。
3. **控件**：奶油色正面、焦糖色边缘、浅色上缘高光、下方短阴影，形成统一的玩具般立体感；层次来自组件本体，不在背景上画不可点击的假按钮。
4. **信息**：先看到波次/剩余敌人、战斗目标与可出牌，再看金币、卡费和说明。活动式密集入口不进入局内。

## 2. 颜色语义（建议值，待现有素材和真机校色）

以下十六进制是**本项目候选 token**，不是从参考录屏取出的精确颜色。一个 token 对应一种用途，正式美术可用同色相的明暗变化，但文字对比要用前景 token 复核。

| Token | 候选色 | 用途与限制 |
|---|---|---|
| `surface/cream` | `#FFF0DA` | 面板与卡牌信息底；局内文字优先放在此类稳定底色上 |
| `surface/raised` | `#FFF9EF` | 按钮、弹窗的亮面；高光面积小于正面，不覆盖文字 |
| `edge/caramel` | `#A65F2F` | 厚边与按压凹槽；不要用作正文色 |
| `ink/primary` | `#704026` | 浅面上的主文案；与 `surface/cream` 的计算对比约 7.64:1 |
| `ink/deep` | `#52341E` | 绿色操作面的文案和重要轮廓 |
| `action/amber` | `#FFC24B` | 主操作按钮与金币强调；不能仅靠金色区分购买成功 |
| `action/green` | `#70C85B` | 可执行与成功；配 `ink/deep` 计算对比约 5.41:1 |
| `danger/red` | `#B8443E` | 危险、受损与失败文字底；搭 `surface/raised` 计算对比约 5.10:1 |
| `disabled/face` | `#EAD7BF` | 禁用表面，仍保留轮廓与原因文案 |
| `ink/secondary` | `#66564D` | 次级说明；与 `disabled/face` 计算对比约 4.98:1 |

数值是按十六进制色块计算的**平面文字对比**，不代表渐变、透明叠层或真机截图已经通过。HUD 的颜色不能只在设计稿里成立，需在背景最亮/最暗的真实战斗帧核对。

## 3. 字体和文案

- 当前可复用字体：中文 `ZCOOL KuaiLe Regular`；英文与数字 `Fredoka` 600。字体和 OFL 授权文件位于 `tools/fonts/`。首页画面内烘焙文字暂不等同于运行时字形。
- 四级层次以当前 390 宽设计基准为起点：主标题 48、面板标题 28、关键数字与按钮 28 或 18、说明与短提示 18。运行时只使用已有 `font-48/28/18` 位图路径并按布局缩放；不凭生图生成文字。
- 浅底用 `ink/primary` 或 `ink/deep`；深色按钮如需白字，先加深底色再验证对比。标题可有轻描边/短阴影，正文优先清晰字面，不使用大范围发光。
- 中文、英文、数字共同对齐基线；不要用「波」「金」「席」等单字缩写。信息过长时先改文案，再考虑折行；不以压小字号解决。
- **顶部 HUD**：只显示「第 x/10 波」「剩余敌人 x」和暂停；窄屏可写「第x/10波」「剩余x」。合照完好度跟随相框，金币在商店，卡费在卡牌，上场人数不常驻。

## 4. 组件结构

| 组件 | 固定规则 | 状态与禁忌 |
|---|---|---|
| 主按钮 | 轮廓、面、上缘高光、下缘厚度、短阴影分层；文字居中 | 按下缩短阴影并下沉，松开回弹；缩放只作用于透明按钮本体，不带背景边缘 |
| 次级按钮 | 与主按钮同光源和边缘语言，饱和度低于主按钮 | 暂停、返回、设置等按功能区别图形，不做多个同亮度争焦点的主按钮 |
| 顶部 HUD | 52px 高的紧凑牌匾，两个文字安全槽，暂停控件单独有热区 | 不放守护物血量或上场数量；背景铺满与 HUD 热区是两层 |
| 英雄卡 | 四格商店约束不变；角色头像、名称/定位、价格分别有独立视觉区 | 卡费徽章仍按现有卡牌布局；不足金币和席位已满分别有明确短文案 |
| 弹窗 | 面板与背景遮罩分层，标题和正文在奶油色稳定底上 | 关闭键位于交互安全区，遮罩期间冻结下层输入 |

几何均从 `Layout.ui` 与 `interactiveRect` 取得。参考 390 宽并非固定设备像素；所有可点击控件及部署落点遵守实际安全区，展示背景可以铺满画布。建议触摸目标短边至少 44 设计单位，实际尺寸还须根据设备缩放检查。正式组件应有透明边界、明确裁切范围与可复用的状态，不把一张完整界面图当作交互层。

## 5. 图标系统

- 功能图标先定义**语义及轮廓**：暂停=双竖条，播放=三角，刷新=单向循环箭头，信息=圆点+i，金币=圆币，扩建=加号或席位扩展，危险=叹号，锁定=锁。爪印只用于本游戏品牌装饰，不替代金币或状态。
- 同一图标族的视重、圆角、边缘厚度与光源方向一致。先在 24/32/48 设计尺寸缩小预览，再加高光和纹理；小尺寸仍要靠轮廓辨识。
- 状态角标用颜色**加**形状/短文案表达；例如金币不足伴随钱币与「金币不足」，席位已满伴随「席位已满」，不只变灰或变红。
- 功能图标优先矢量或 WebGL 形状；猫狗、家具、合照等具象图标可从本项目原创角色美术制作，但需重新检查透明边与图集尺寸。录屏截图和概念小样均不作为游戏纹理。

## 6. 审核与接入门槛

1. **本轮审核**：检查原创小样的材质、高光、厚度和状态；审核 token、文字层级与图标语义。小样里不合规则的卡费位置和爪印金币不进入正式资源。
2. **组件落地前**：分别产出按钮、面板、卡牌的透明独立素材或可绘制参数；核对 390/414 宽和窄屏排版，不修改战斗数值与输入判定。
3. **运行时验收**：H5 与 iOS/Android 真机检查文字锐度、背景最亮/暗处对比、按压反馈、命中区一致性、十角色同场遮挡。材质和图标在小尺寸下仍可辨。
4. **包体门槛**：概念小样只保存在 `design/`，不进入 `package/`。当前主包记录约 15.35 MiB，高于 6 MiB 上限；正式资产接入前需先核算预算，避免只叠加图片。

此稿没有改变任何游戏代码或正式美术。通过审核后，再将每个组件分批实现和对照验收。
