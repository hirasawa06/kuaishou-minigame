# 屏幕安全区与平台按钮设计规范

状态：项目设计基线；2026-11-03。以合入 `main` 的版本为生效版本；规范生效不代表游戏代码已经完成适配。

## 1. 适用范围与依据

本规范适用于《猫狗大战家具》及当前 `tower-defense/` Demo 的所有游戏内场景，包括首页、家中总览、战斗、暂停、结算、弹窗和拖拽交互。首版产品方向为竖屏；横屏规则保留为平台兼容基线，不属于首版玩法验收范围。

依据按以下优先级解释：

1. 快手真机返回的系统安全区与平台控件实际占位。
2. 仓库锁定的 `ks-yoola-devkit 0.0.1` 及其互动玩法设计规范 V2.0。
3. 本文记录的区域语义、布局合同与验收规则。
4. 414×896、896×414 设计图和像素数字仅作比例与兜底参考，不是固定运行分辨率。

历史资料对 Android 顶部参考值存在 `20px` 与 `40px` 两种记录。本文不选择其中任一数值作为硬编码标准；运行时必须读取设备信息。只有在平台信息缺失时，才采用不侵入系统区域的保守兜底，并把该设备列入真机复核。

## 2. 五区语义

| 区域 | 定义 | 约束 |
|---|---|---|
| A 系统安全区 | 刘海、状态栏、圆角和开孔等系统保留区域 | 禁止放置游戏内容与触摸热区；以设备实际安全边界为准 |
| B 间距保护 | 系统区域、平台控件与自定义 HUD 之间的呼吸空间 | 参考 `32px`；不得用装饰或透明按钮占用 |
| C 平台控件预留 | 快手平台功能按钮及其操作范围 | 参考高度 `64px`，实际控件占位优先；禁止遮挡、重叠和抢占触摸 |
| D 可交互游戏区 | 核心玩法、HUD、道具、卡牌和操作热区 | 必须由安全边界动态计算；核心玩法优先完整显示 |
| E 底部安全区 | 系统手势条及底部手势冲突区域 | iOS 竖屏参考 `68px`、横屏参考 `42px`；实际底部边界优先 |

颜色只用于设计图中的区域标注，不代表正式 UI 配色；区域高度也不能直接照搬设计图。

## 3. 竖屏布局合同

竖屏是当前唯一产品方向。布局顺序为：

`系统安全区 → 保护间距 → 平台控件预留 → 可交互游戏区 → 底部安全区`

运行时应先统一到逻辑像素坐标，再计算：

- `systemTop`：系统顶部安全边界，来源为平台封装返回的 `safeArea.top` 或状态栏信息。
- `safeBottomY`：底部安全边界坐标，优先使用 `safeArea.bottom`；它是坐标，不是底部间距。
- `bottomInset = viewportH - safeBottomY`。
- `platformTop/platformBottom`：平台控件实际矩形；接口不能提供时，使用 `systemTop + 32px` 起、至少 `64px` 高的整行预留。
- `contentTop`：不得早于平台控件预留区的下边界；如能获得实际控件矩形，还须保证自定义 HUD 与控件之间有足够保护间距。
- `contentBottom`：不得晚于 `safeBottomY`。
- `contentH = contentBottom - contentTop`。

战斗 HUD、战场、资源条和卡牌托盘只能在 `[contentTop, contentBottom]` 内重新分配空间。高度不足时按以下顺序处理：

1. 压缩纯装饰留白和非必要说明。
2. 缩减不影响识别的 HUD 间距。
3. 保持核心目标、来袭方向、战场落点、资源和全部手牌可见。
4. 保持按钮与卡牌热区可触达，不得通过裁切核心对象来“适配”。
5. 仍无法满足时记录为适配缺陷，不静默降级或让内容越过安全区。

## 4. 横屏留档规则

横屏不复用竖屏坐标。系统开孔可能转移到左右两侧，必须根据方向换算安全边界，并同步处理 Canvas 方向和触摸映射。

- 顶部保护间距参考 `32px`。
- 平台控件预留参考 `64px`，实际占位优先。
- iOS 底部安全区参考 `42px`，Android 读取实际安全边界。
- 核心内容、HUD 和按钮须避开侧边开孔。
- 横屏适配启用前必须单独设计、实现和真机验收，不能因为 H5 旋转后可见就宣称支持。

## 5. 视觉与交互一致性

- 所有绘制位置与触摸命中必须来自同一份布局数据，不维护两套坐标。
- 触摸事件先从屏幕坐标转换为逻辑像素；DPR 只影响 backing store 和 WebGL viewport，不影响业务布局值。
- 拖拽卡影可以向手指上方偏移以避免遮挡，但释放结算使用真实手指逻辑坐标。
- 卡牌起拖区、战场落点、暂停按钮、弹窗按钮和道具按钮不得进入 A、C、E 区。
- 热区可大于视觉轮廓，但不能跨入系统或平台保留区；状态变化后视觉与热区必须同步更新。
- 布局在尺寸或方向变化时统一重算，不在每一帧查询系统信息。

## 6. 画面层级约束

- 平台控件层级最高，游戏不得绘制仿冒控件或用视觉元素遮盖。
- 自定义 HUD 位于可交互游戏区顶部，不把 `safeTop` 当作 HUD 起点。
- 核心战场优先于装饰背景；背景允许延伸到屏幕边缘，但不能包含需要阅读或点击的关键信息。
- 底部卡牌、主要操作按钮和付费/广告入口必须完整位于可交互区。
- 弹窗遮罩可以覆盖游戏画面，但确认、取消和关闭按钮仍须遵守安全区与平台控件避让。

## 7. 实现边界

- 使用 `AIGCUtils.Layout` 作为统一布局出口，业务模块只读取计算结果。
- 通过平台封装能力读取设备信息；玩法代码不直接调用裸 `ks.*`。
- 使用 WebGL 1.0 自绘，不以 DOM、CSS 或 Canvas 2D 修补安全区。
- `index.html` 只模拟预览尺寸，不能成为真机安全区数据来源。
- 如果现有封装没有提供平台按钮矩形或完整安全边界，先采用整行保守预留并记录待验证项，不自行假造平台 API。

本文不决定 `kwaiStandard/` 是否允许修改。适配层只读与模板占位绘制例外属于开发规范问题，须在独立工程决策中统一。

## 8. 当前 Demo 实施状态

当前实现已经通过 `KwaiBase.getSystemInfo()` 读取系统安全区域，并由 `gameplay/layout.js` 统一计算顶部保护间距、平台控件预留、左右安全边界、底部安全边界和可交互区域。HUD、暂停按钮、战场、卡牌及菜单按钮均由同一布局结果派生。

仍待完成：

- 平台暂未提供控件实际矩形时，当前采用整行 `32px + 64px` 保守预留；需在真机确认不会过度或不足避让。
- iOS / Android 真机安全区、平台按钮、命中一致性和比例变化验收。
- 横屏规则只留档，当前产品与代码均以竖屏为首版范围。

因此当前状态是“设计规范已实现并通过本地回归，等待真机验收”，不能标记为“已通过平台适配”。

## 9. 验收清单

### 自动与桌面检查

- 不存在从 `y = 0` 开始放置的关键内容或交互控件。
- 绘制矩形与命中矩形来自同一布局对象。
- 414×896 及至少一组更窄、更高和更矮的竖屏尺寸均无裁切、重叠和溢出。
- DPR 变化后视觉与触摸仍对齐。
- H5 预览只记为快速回归，不替代真机结论。

### 真机检查

- iOS 与 Android 各至少一台设备。
- 平台按钮无遮挡、无重叠、无误触。
- 核心目标、敌人来向、战场落点、资源与全部手牌完整可见。
- 拖拽起点、预览、释放落点与最终结算一致。
- 暂停、结算、弹窗和底部按钮不与系统手势冲突。
- 前后台切换、方向变化或尺寸刷新后布局重新计算且不跳位。

验收结果须记录设备、系统、方向、构建提交、截图或录屏以及发现的问题；没有真机证据时不得写“已通过平台适配”。
