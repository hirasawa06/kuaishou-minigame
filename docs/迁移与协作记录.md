# 策划迁入与协作边界

更新：2026-11-03。记录基点是本仓库当前路径：仓库根目录负责协作与策划，`tower-defense/` 负责唯一游戏工程。后续把有用的策划约束纳入这里。

## 当前路径与真源

| 路径 | 作用 | 变更条件 |
|---|---|---|
| `tower-defense/package/` | 当前小游戏实际代码与资源 | 单独工程分支实现、测试后合并 |
| `tower-defense/PROJECT.md`、`aigc-context.json` | 当前项目的技术约定与状态 | 实际能力和阶段变化后更新 |
| `ks-yoola-devkit/` | 随仓库锁定的平台开发规范 | 升级时核对差异，不覆盖旧模板 |
| 根目录 `docs/` | 本项目经整理的策划与协作说明 | 区分已确认、提案、待验证，再进入工程任务 |
| 根目录 `STATUS.md`、`CHANGELOG.md` | 当前交接和版本变化 | 每次里程碑更新，并附提交与验证依据 |

协作记录位于仓库根目录；基础策划由 `codex/planning-foundation` 整理。分支及 PR 状态以 GitHub 实际记录为准。无论策划文档是否合并，当前工程行为仍以代码和 `tower-defense/PROJECT.md` 为准。

## 已确认的表现规则

### 后续美术镜头统一为 60°正北（2026-11-08，已确认）

- 来源：用户明确要求将后续新制素材的统一俯角由 70°改为 60°；状态：规范与透视预演页已更新，普通柜怪 60°三视图已确认并归档为结构母版。
- 决定：相机固定在战场正南、朝正北，俯角固定 60°。后续新制或重制的角色、怪物、飞弹与特效均遵守此镜头，并在接入前用 `tower-defense/tools/camera-perspective.html` 预演。
- 边界：已验收的 70°素材及台灯小怪既有的 45°素材保留，不因本次标准变更返工；只有用户另行要求重制时才切换为 60°。

### 普通柜怪首轮行动（2026-11-08，已实现，待真机验证）

- 决定：普通柜怪以四脚交替的小步移动，柜体前倾后回正；不使用台灯小怪的跳步。攻击先整体下沉后仰，再以黄眼所在的上沿为先整体前探撞击，在 0.24 秒命中；抽屉保持闭合，不作为武器。
- 决定：普通柜怪的逻辑直径从当前 30 调为 40，贴图主体宽度维持已确认的 55–60；攻击、生命、攻速、移速、金币与波次数值不变。
- 实现：动作源为 `tower-defense/tools/src/characters/角色/普通柜怪/普通柜怪动作-v1.png`（2×2），由 `normal.json` 驱动图集与 `normal` Rig；图集为 1024×1152、68 格，普通怪半径已从 15 改为 20。资源门禁、400 秒仿真、布局与包体预检通过；快手真机尚未验证。
- 边界：本轮只制作待机、迈步、攻击蓄力与攻击命中四帧；受击、倒地与其他敌人不在本轮范围。

### 战场角色体积与南北遮挡（2026-11-08，已确认）

- 来源：本次用户对角色前后关系和穿模问题的明确要求；状态：已在当前工程分支实现，待人工 H5 与快手真机验收。
- 决定：角色前后关系按脚下落点排序，而非按“宠物 / 怪物”类型排序。北侧角色先绘制，南侧角色后绘制并自然遮住北侧角色；排序点与各自实际阴影中心一致。
- 决定：现有 `radius` 作为脚底圆形碰撞体。所有存活宠物与怪物必须保持半径和加 2 逻辑像素的间距；攻击距离、嘲讽距离、血条和贴图绘制尺寸不因此改变。
- 决定：固定部署的宠物不被怪物推走；主动出击的锤锤喵与怪物可互相避让。怪物撞上固定宠物时优先向北侧排队，不能被挤到宠物和基地之间。新宠物不能直接部署在怪物或其他宠物的占地内，失败时不扣金币。
- 实现补充：同一路怪物只做纵向排队，不参与四向互推；锤锤喵若在一帧内同时贴近多个目标而仍重叠，才搜索一个同时避开全部存活单位的近处站位。该补救不移动固定部署宠物，也不改攻击距离或伤害。

### 战场单位底座（2026-11-07，已确认）

- 来源：本次用户对战场视觉的调整；状态：已在当前工程分支实现，并通过本地回归，待合并。
- 决定：所有宠物和怪物保留近黑色、横向椭圆且边缘羽化的脚下阴影，面积系数为 0.70；宠物最大不透明度为 0.40，怪物按原比例提升至 0.48。宠物阴影必须按实际贴图脚底定位，不得按逻辑半径中心绘制而被贴图遮住。移除常驻色块 / 光环、减速环、首领环和战士驻点环。
- 影响：血条与攻击、命中、死亡等短暂特效继续保留，战斗数值和状态逻辑不变。

### 角色 AI 生图参考链（2026-11-05，已确认）

### 台灯小怪（2026-11-05，已合入 main）

- 实现：六帧透明动作表放在 `tools/src/characters/角色/台灯小怪/lamp-minion-actions-v2.png`，正 / 侧 / 后三视图参考放在同目录 `台灯小怪三视图参考-v2.png`，由 `lamp.json` 驱动图集与 Rig。两份素材均按已确认的情绪版风格图与台灯三视图生成，固定 45° 斜俯视。受击后仰，死亡侧翻后直接移除、不复用白烟雾；撞击命中使用暖色冲击效果。

### 近战猫（2026-11-05，已确认）

- 来源：本次用户提供的近战猫三视图；状态：已替换移动近战位 `war` 的可见角色，保持其 id、商店位置和战斗数值不变。

### 宠物统一尺寸规范（2026-11-07，已确认，已完成首轮数值落地）

- 来源：本次用户确认的尺寸规范替换；状态：已写入《角色行动动画制作规范》，并完成首轮运行时数值落地。
- 决定：用户确认逻辑占地和贴图均整体等比扩大 1.2 倍；落地为柴不破 45.6 / 60、锤锤喵 43.2 / 57.6、镭射喵 40.8 / 55.2、哈利边牧 40.8 / 55.2（逻辑直径 / 贴图绘制参考尺寸，414 宽基准）。为补偿变大后敌人更早接战，宠物攻击、嘲讽、追击及范围伤害距离、生命和攻击力也同步 ×1.2；攻速和怪物参数不变。
- 决定：逻辑直径不要求大于完整绘制外框；以待机可见主体宽度为比较基准，统一占地 / 主体比例为 68–83%。
- 决定：怪物按小怪、普通、精英、首领 / 巨型家具怪分档，逻辑直径可为 18–24、26–34、36–48、50–80 或 84–120；脚底占地决定逻辑尺寸，高度、装饰和攻击外框仅影响绘制。巨型怪跨通路时另行定义阻挡与受击规则。
- 待实现：将目前复用的 `radius` 拆为 `footprintRadius`、`hitRadius`、`renderScale`，并让部署间距按双方占地半径计算；该变更会影响阻挡和攻击距离，须单独回归。

### 盾狗背面受击与晕倒（2026-11-05，已合入 main）

- 来源：本次用户确认的盾狗表现；状态：已在工作区实现。
- 决定：盾狗不攻击；战场待机与受击均使用背视。嘲讽维持原有的敌人目标选择规则，但不播放光盾；受击必须有可见后移下沉与回正。
- 决定：盾狗受击维持背视；被击败时向后仰面倒地，头朝战场南侧。倒地姿势全程不渐隐，随后使用所有角色共用的三帧纯白烟雾直接移除。
- 实现：源图放 `tools/src/characters/角色/盾狗/`，`tank.json` 驱动图集和 Rig；正面柴犬分件不再进入战场，仅供卡牌头像使用；光盾源图与运行时渲染已移除。

### 角色行动动画制作规范（2026-11-05，已合入 main）

- 来源：本次用户确认的后续制作流程；状态：已写入《角色行动动画制作规范》。
- 决定：未来新增角色可只提供角色图与角色特点；实现方按职业特点自动判断行动样式、方向帧、命中时刻、分件或整体姿势帧方案与通用特效复用方式。
- 决定：角色动作源按角色目录归档，死亡烟雾等可复用效果独立归档在 `tools/src/effects/`；攻击伤害与投射物起点必须来自 Rig 数据，不能为角色另写硬编码时间点。
- 实现：英雄和敌人统一经过 `idle / move / atk / hurt / die` 生命周期；死亡完成后播放通用烟雾。动作规格 JSON 是图集与 Rig 的单一来源，图集自动排格并在冲突或容量耗尽时失败。

### 射手猫背面单发攻击（2026-11-04，已合入 main）

- 来源：本次用户确认的实现请求；状态：已在 `petsAndFurniture-art-assets` 工作区实现，并经整合分支完整回归后合入 `main`。
- 决定：本次先将射手猫的战场表现固定为背面动作；攻击节奏为蓄力 0.10 秒、独立开火姿势 0.12–0.18 秒并发射一枚光弹、0.46 秒回到待机。目标在左右两侧时分别使用对应动作，但枪始终由角色右手持有。伤害只在该光弹到达目标时结算。
- 决定：射手猫被击败时向身后倒下，使用用户提供的“仰面倒地”姿势：脸在战场南侧、身体与尾巴朝北侧，保留螺旋眼和星环。姿势全程保持不透明，落地后播放三帧纯白烟雾并直接移除单位。
- 实现：角色原始参考与动作源统一归档在 `tools/src/characters/角色/<角色名>/`，不再将多个角色素材平铺在 `角色/` 根目录；跨角色风格参考归档在 `tools/src/characters/情绪版/`，全角色共用的死亡烟雾归档在 `tools/src/effects/defeat-smoke/`。
- 工程影响：角色动作采用离线图集帧，枪口和单发光弹由 WebGL 加法混合绘制；原始角色参考素材迁出 `package/res/`，不参与游戏包体。
- 待验证：快手 iOS / Android 真机的纹理内存、帧率与视觉可读性；正面动作尚未制作。

## 只迁入有用的限定

| 类型 | 迁入内容 | 如何使用 |
|---|---|---|
| 产品目标 | 游戏方向为《猫狗大战家具》；快手用户；操作爽感优先，收集猫狗服务于新的操作体验 | 写入策划总览，待团队确认具体玩法实现 |
| 体验结构 | 家中总览承担关卡衔接，单局战斗独立设计；正式产品期望连续游玩 30–60 分钟 | 用于规划关卡与中断恢复，不作为现有 Demo 单局时长承诺 |
| 世界观 | 异变家具与猫狗守护生活物品；家具功能与动机应关联关卡 | 作为关卡和角色设计依据，细节仍是提案 |
| 平台约束 | 独立 JS Runtime、WebGL 1.0 自绘、单机、本地资源、安全区动态适配、平台 API 经封装层 | 与本仓库 Skill 及真机结果核对后落实；适配层只读冲突单独处理 |
| 协作方式 | 策划、工程、测试各自记录证据；`main` 保持可运行，短期分支审阅后合并 | 作为跨会话和跨设备的工作约定 |

## 不迁入的内容

- 其他工程的 `game/` 代码、脚手架状态、包、素材、测试结果和版本号。
- 旧白盒的具体数值、路线、牌序和实现方式；如需参考，先与当前 Demo 对照并单独决策。
- 未确认的商城、体力、道具、抽取、广告位置等提案；它们不能因出现在参考图或历史草案中而成为需求。
