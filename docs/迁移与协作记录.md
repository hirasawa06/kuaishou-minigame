# 策划迁入与协作边界

更新：2026-11-03。记录基点是本仓库当前路径：仓库根目录负责协作与策划，`tower-defense/` 负责唯一游戏工程。后续把有用的策划约束纳入这里。

## 当前路径与真源

| 路径 | 作用 | 变更条件 |
|---|---|---|
| `tower-defense/package/` | 当前小游戏实际代码与资源 | 单独工程分支实现、测试后合并 |
| `tower-defense/PROJECT.md`、`aigc-context.json` | 当前项目的技术约定与状态 | 实际能力和阶段变化后更新 |
| `ks-yoola-devkit/` | 随仓库锁定的平台开发规范 | 升级时核对差异，不覆盖旧模板 |
| 根目录 `docs/` | 本项目经整理的策划与协作说明 | 区分已确认、提案、待验证，再进入工程任务 |
| 根目录 `STATUS.md`、`CHANGELOG.md` | 当前交接和版本变化 | 每次里程碑更新，并附提交与验证依据 |

协作记录位于仓库根目录；基础策划由 `codex/planning-foundation` 整理。分支及 PR 状态以 GitHub 实际记录为准。无论策划文档是否合并，当前工程行为仍以代码和 `tower-defense/PROJECT.md` 为准。

## 只迁入有用的限定

| 类型 | 迁入内容 | 如何使用 |
|---|---|---|
| 产品目标 | 游戏方向为《猫狗大战家具》；快手用户；操作爽感优先，收集猫狗服务于新的操作体验 | 写入策划总览，待团队确认具体玩法实现 |
| 体验结构 | 家中总览承担关卡衔接，单局战斗独立设计；正式产品期望连续游玩 30–60 分钟 | 用于规划关卡与中断恢复，不作为现有 Demo 单局时长承诺 |
| 世界观 | 异变家具与猫狗守护生活物品；家具功能与动机应关联关卡 | 作为关卡和角色设计依据，细节仍是提案 |
| 平台约束 | 独立 JS Runtime、WebGL 1.0 自绘、单机、本地资源、安全区动态适配、平台 API 经封装层 | 与本仓库 Skill 及真机结果核对后落实；适配层只读冲突单独处理 |
| 协作方式 | 策划、工程、测试各自记录证据；`main` 保持可运行，短期分支审阅后合并 | 作为跨会话和跨设备的工作约定 |

## 不迁入的内容

- 其他工程的 `game/` 代码、脚手架状态、包、素材、测试结果和版本号。
- 旧白盒的具体数值、路线、牌序和实现方式；如需参考，先与当前 Demo 对照并单独决策。
- 未确认的商城、体力、道具、抽取、广告位置等提案；它们不能因出现在参考图或历史草案中而成为需求。

## 后续维护

新的策划结论写明来源、日期、决定者及对当前 Demo 的影响。跨设备通过本仓库的 Git 分支和提交恢复状态；本地目录名只是一种检出位置。真机测试和平台审核以实际记录为准，不能从 H5 预览推断。
