# 角色行动动画制作规范

状态：**已确认**（2026-11-05）
适用范围：`tower-defense/` 的英雄、敌人、召唤物；通用特效不归属于任何角色。

## 1. 目标与原则

每次新增角色，输入可以只有“角色图 + 角色特点”。实现方负责根据特点选择行动样式、动作集、朝向需求、命中时刻和特效复用方式，再以可运行的图集与 Rig 交付。

- 动作服务于战斗信息：玩家必须一眼看出角色在待机、蓄力、出手、受击或退场。
- 角色姿势与伤害结算必须同一时间线；禁止在起手即扣血后再播放出手动作。
- 通用烟雾、光弹、命中火花等只存放在 `tools/src/effects/`，不可复制到角色目录。
- 优先复用通用状态名：`idle`、`move`、`atk`、`hurt`、`die`；只有确有独立玩法含义时才增加状态。
- 在 WebGL 1.0 图集约束下，优先以少量、辨识度高的帧表达动作，避免无意义的逐帧堆量。

## 2. 输入与自动决策

用户提供角色图与特点后，按下表自动选择基础动作方案。未指定的细节按默认项实现，并在交付时写明。

| 角色特点 | 默认行动样式 | 最小动作集 | 额外规则 |
|---|---|---|---|
| 防御、护盾、嘲讽 | 稳定站桩、重心后压、格挡前顶 | idle / hurt / die；有攻击时再加 atk | 手持盾牌与罩体护盾必须分开：手持物可随角色或分件，罩体作为独立特效；纯嘲讽角色不创建 atk；受击须包含可见位移或重心变化 |
| 近战、冲锋、追击 | 呼吸待机、前倾移动、短促挥击或撞击 | idle / move / atk / hurt / die | 面向移动或目标方向；命中设在接触姿势 |
| 射手、枪械、弓箭、单发远程 | 轻幅瞄准、明确开火帧、小幅后坐 | idle / atk / hurt / die | 左右目标导致持械姿势不一致时提供左右开火帧；投射物由运行时绘制 |
| 法师、范围攻击 | 蓄力、施法、能量释放、收势 | idle / atk / hurt / die | 范围、拖尾、光圈属于通用或技能特效，不烘焙在角色帧 |
| 治疗、辅助、召唤 | 朝友方施法、抬手或道具前送 | idle / atk / hurt / die | `atk` 的目标可为友方；治疗光效由运行时绘制 |
| 家具怪、静态敌人 | 短促抖动、弹跳、碰撞或开合 | idle / atk / hurt / die | 体积大但无独立部件时优先整体姿势帧 |
| 首领、多阶段单位 | 保持清晰轮廓，重击动作更长 | idle / atk / hurt / die，可加 phase | 新状态必须有明确战斗规则，不以美术复杂度为理由增加 |

默认节奏：待机循环 2.0–2.6 秒；常规攻击 0.35–0.55 秒；受击 0.18–0.25 秒；死亡 0.35–0.60 秒。实际数值可按武器重量、攻击距离和角色体积调整。

## 3. 素材目录与命名

角色源图按角色存放；通用特效独立存放：

```text
tools/src/
├── characters/
│   └── 角色/
│       └── <角色名>/
│           ├── <角色名>-参考.png
│           ├── <角色名>-attack-sheet.png
│           ├── <角色名>-fire-left.png     # 仅左右姿势确有区别时
│           ├── <角色名>-fire-right.png
│           └── <角色名>-defeat.png
└── effects/
    └── <特效名>/
        ├── <特效名>-01.png
        ├── <特效名>-02.png
        └── <特效名>-03.png
```

- 所有源图必须为 PNG + 透明背景；角色帧不带场景、地面、HUD、文字或独立飞行特效。
- 完整姿势帧以角色脚底或约定落点为统一基线；分件帧必须以同一完整角色画布为参照，不可分别居中。
- 帧名表达用途而不是生成方式，例如 `fire-left`、`recoil`、`defeat`；废弃版本加 `-legacy`，不得覆盖已验收帧。
- 跨角色风格参考放在 `tools/src/characters/情绪版/`；不得借角色名建立上层容器，避免把非射手角色误归入 `archer`。

## 4. 图集接入

1. 先创建 `tools/src/animation-specs/<角色id>.json`，记录角色 id、源目录、帧名、动作时长、`hit`、朝向帧与 `muzzle`。
2. 在 `tools/gen-shiba-atlas.py` 注册该规格；脚本会读取规格并生成运行时动作数据，禁止在 Rig 与图集脚本重复填写攻击时刻、枪口或帧名。
3. 使用 `fit_visible()` 裁去透明边缘并放入 128px 单元格（有效区 120px）。
4. 图集格位由生成器按注册顺序自动分配；重复帧名、格位耗尽或规格字段缺失必须使生成失败。
5. 生成图集与运行时动作数据：

```bash
cd tower-defense
python3 tools/gen-shiba-atlas.py
```

生成结果只能是 `package/res/Image/game.png`、`package/gameplay/data/rigs.js` 与 `package/gameplay/data/character-animations.js`；原始参考图不能进入 `package/res/`。

## 5. Rig 与战斗绑定

在 `package/gameplay/anim/defs.js` 为角色建立 Rig：

- `parts`：整体姿势帧通常只需一个 part；护盾、武器等可独立运动时拆分 part。
- `states`：使用标准状态名，关键帧只记录 `dx`、`dy`、`rot`、`sx`、`sy`、`alpha` 与离散 `icon` 切换。
- `states.atk.hit`：唯一的攻击出手时刻；`battle.js` 从此字段读取结算时间。
- `muzzle`：远程单位的投射物起点；没有投射物则不配置。
- `die.dur`：死亡姿势保持时间；单位在动画结束后才移除并触发通用退场特效。
- `move`：移动实体进入移动状态；尚未制作移动 Rig 时自动回退 `idle`，制作后无需改战斗循环即可生效。

在 `config.js` 给角色定义数值和类别。若攻击朝向需要不同姿势，则配置 `attackRig: { left, right }`；`battle.js` 依据目标横向位置选择 Rig。

除非新增玩法规则，禁止为单个角色在 `battle.js` 写死攻击时间、枪口坐标或死亡时长。

## 6. 通用特效

- 死亡烟雾当前使用 `tools/src/effects/defeat-smoke/` 的三帧白色素材，并在 `scene.js` 按生命周期播放 `fx-smoke`、`fx-smoke-2`、`fx-smoke-3`。
- 英雄与敌人共用 `die → 烟雾 → 移除` 生命周期；未制作专属死亡 Rig 的单位使用短暂静态退场，再播放通用烟雾。
- 光弹、命中闪点、范围圈、火花均由 WebGL 运行时绘制；角色图只表达动作本身。
- 新通用特效必须可被多个角色复用；如只表达某角色的专属技能，再放入该角色目录并以技能名区分。

## 7. 验收清单

每个角色动画完成后，必须依次通过：

```bash
python3 tools/gen-shiba-atlas.py
node tools/assets-check.mjs
node tools/sim.mjs --seconds 400
node tools/layout-check.mjs
node --experimental-websocket tools/anim-shot.mjs --hero <角色id> --target left --port 8103
node --experimental-websocket tools/anim-shot.mjs --hero <角色id> --target right --port 8103
node --experimental-websocket tools/anim-shot.mjs --entity enemy --hero <敌人id> --port 8103
node --experimental-websocket tools/shot.mjs --port 8103
node ../ks-yoola-devkit/scripts/validate-package.mjs --dir .
```

人工验收重点：动作方向、持械手、出手与伤害时刻、投射物起点、脚底基线、死亡姿势、通用烟雾播放顺序，以及缩放后在手机尺寸上的可读性。

`hurt` 不能仅替换一张近似待机的姿势帧：在手机尺寸定格与实际播放中，必须能看出至少一种后移、下沉、失衡、缩放或回弹；防护罩则必须保留角色可见性，并以体积、厚度和高光表达 3D 质感。
