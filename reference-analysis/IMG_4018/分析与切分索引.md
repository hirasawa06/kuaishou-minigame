## 值得借鉴的部分

1. **材质与视觉层级**：暖色立体场景、圆润按钮、柔和高光和接触阴影让画面像可触摸的玩具。我们的猫狗、家具与客厅可借鉴这套材质语言，但配色仍以现有首页与战场资产为准。
2. **按钮反馈链**：按下时轻压、松开时弹回、成功后短暂高亮与奖励飞入是连续动作。应用到首页按钮、商店刷新、卡牌购买、暂停/继续；要让反馈贴合按钮透明轮廓，不缩放背景切片。
3. **拖动与落地**：元素抬起、跟手、合法落点强调、落地弹性与短时粒子是可迁移的交互语法。用于猫狗卡牌上阵；部署合法性必须继续由我们的战斗规则判定。
4. **信息遮罩**：打开任务、奖励或三选一面板时，背景压暗且暂停输入，关闭后回到原位置。可用于角色详情、暂停、结算和未来的收集展示。
5. **奖励聚焦**：角色卡获得时先压暗战场、再聚焦单张卡、随后回到原流程。适用于猫狗解锁；不需要复制其稀有度、抽卡或付费结构。
6. **局外空间连接**：家中场景作为功能与关卡入口，比静态菜单更有记忆点。可用于已规划的家中总览；当前单人 Demo 无需一次做完多房间系统。

## 字体、文字与颜色也纳入参考

以下是从录屏画面观察出的**视觉特征**，不是对原游戏字体文件或精确色值的识别。重点参考 [02 主界面](clips/02_home.mp4)、[05 任务面板](clips/05_tasks_rewards.mp4)、[07 卡牌奖励](clips/07_card_reward.mp4)、[09 局内循环](clips/09_board_core_loop.mp4) 和 [13 通行证](clips/13_event_pass.mp4)。

| 观察维度 | 录屏中的做法 | 转译到《猫狗大战家具》 |
|---|---|---|
| 字体气质 | 中文是较厚、圆润、紧凑的卡通黑体；标题常加深色描边或投影，数字也有足够重量 | 统一首页、战斗 HUD、卡牌、弹窗的字形体系；不用细黑体或写实衬线体。当前字形图集需以快手 WebGL 的实际尺寸检验笔画清晰度 |
| 文字层级 | 大标题、按钮文字、数值、说明文案形成明显四级；按钮用短动词，重要数字放在色块或徽章里 | 战斗中优先读到波次、合照完好度、金币与卡费；角色细节放详情层，避免 HUD 挤满句子 |
| 文字对比 | 奶油白面板配深紫灰字；深色/彩色面板配白字和深色细描边；强调数字用黄、粉等高亮色 | 以奶油白＋暖棕为我方界面基础，危险和受损用暖红，资源与成功用金黄/清绿；强调色只标关键状态 |
| 面板颜色 | 主玩法的青绿棋盘、局外暖色场景、紫色活动面板彼此区分，面板有厚边、浅内层和投影 | 借鉴“场景、功能面板、危险反馈分色”的层级，不照搬整套紫/青配色。我们的客厅保留暖木色，战场与卡牌保证猫狗/家具可读 |
| 状态提示 | 完成、获得、可领取等状态有颜色、图标与短文字共同确认 | 合照受击、合法落点、金币不足、席位已满不能只靠红绿区分；配合轮廓、动效或短文案 |

**建议先做的视觉样张**：同一画面并排比较“首页按钮、局内卡牌、顶部 HUD、合照完好度、角色获得弹窗”五类文字，检查字号、描边、字距、数字与底色对比。录屏无法证明其字体名称或精确色号，正式规范应由我们的样张和真机截图反推，不直接声称复刻原作。

## 不应迁移的部分

- 棋盘合成、餐厅订单、顾客队列与棋盘工具，不属于猫狗轻塔防的出牌、落点、阻挡与防守循环。
- 满屏限时活动、转盘、VIP 通行证、多货币栏和不断弹出的付费入口，会遮挡我们需要看清的战场、守护物和部署热区。
- 录屏中的资源、角色、图标与具体 UI 图案只作参考，不直接抽取进游戏。我们的运行时是 WebGL 1.0 自绘，不采用其页面实现方式。
- 录屏不能证明具体触摸热区、缓动参数、运营效果或真机帧率；这些仍需在我们的设备上验证。

## 建议的转译顺序（分析提案）

先建立统一的按钮按压与弹回规则，再做卡牌拖起—跟手—合法落点—上阵反馈，随后处理相框受击、角色解锁和弹窗切换。每一步以“操作是否更清楚、更爽”为验收点，保留战场可读性和安全区约束。暂不改玩法数值和商业化系统。
